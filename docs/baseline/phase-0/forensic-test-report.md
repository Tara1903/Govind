## 1. EXECUTIVE SUMMARY

### What Govind Currently Is
Govind is a hybrid prototype combining an Android Jetpack Compose application (`C:\Web Apps\Govind\android`), a Next.js 16 Admin panel (`C:\Web Apps\Govind\admin`), and a Supabase PostgreSQL backend (`C:\Web Apps\Govind\supabase`). There is **no customer-facing website** in the repository (`admin` is the only web project).

### What Really Works
1. **Android Build & Launch:** APK compiles cleanly, installs on `emulator-5554`, and renders the custom `GovindTheme` design system (`#1E6F3D` green, `#FFFCF7` warm white, `#F5450D` orange).
2. **Email OTP UI & Guest Entry:** First launch presents the passwordless Email OTP screen (`Continue with Email` + `Continue as Guest`). Tapping `Continue as Guest` enters the main app, and typing an email sends a real request to Supabase `POST /auth/v1/otp`.
3. **Live Product Fetch (Read-Only):** The Android app fetches `85` real products and `16` categories from Supabase (`public.products` and `public.categories`).
4. **Local Room Cart & Client-Side Bulk Pricing Math:** Adding items from Fresh, Kitchen, or Wholesale inserts into the local Room `cart_items` table (`CartEntity`), groups them by `experienceType` in `CartScreen`, and runs `BulkPricingEngine.calculateItemPrice` in memory.
5. **Product Search (Basic Query):** Typing a query in `SearchScreen` filters the 85 Supabase products in real time.

### What Only Partially Works
1. **Experience Switcher (`Fresh` / `Kitchen` / `Wholesale`):** Tapping `Kitchen` or `Wholesale` on `PillExperienceSwitcher` updates `AppState.currentExperience` (changing the bottom nav label from `Rates` to `Menu` or `Bulk`), **but `MainAppScreen` stays on `HomeScreen` (`Fresh`)** unless the user taps the middle bottom-nav tab (`KitchenMenu` / `WholesaleHome`). `KitchenHomeScreen` is completely unreachable.
2. **Catalogue Data & Images:** 85 products exist in Supabase, but **79 of 79 `product_images` rows are `https://ui-avatars.com/api/?name=...` text-initials placeholders** (zero real food/produce photography). Several categories (`Fresh Fruits`, `Fresh Vegetables`, `Fresh Combos`, `Ready-to-Cook`, `Restaurant Supply`) have `0` products linked.
3. **Checkout & Order Creation:** `CheckoutScreen` loads, collects a phone number via an inline dialog, and calls the `create_order_and_decrement_stock` RPC. However, it uses **hardcoded fake addresses** (`123 Green Valley...` / `456 Tech Park...`), **hardcoded `₹0.0` delivery fee**, **no StarPay integration** (uses `Razorpay` SDK with placeholder keys or mocked COD), and **crashes on foreign-key violation (`orders_user_id_fkey`)** if the authenticated user lacks a row in `public.profiles` (currently `2` users exist in `auth.users`, `0` rows in `public.profiles`).
4. **Admin Panel (`http://localhost:3005`):** Renders 14 pages with a polished UI, and `/products`, `/fresh-board`, `/daily-rates`, `/punjabi-menu`, and `/orders` query Supabase. However, `/inventory`, `/coupons`, `/promotions`, `/customers`, and `/settings` are **100% static hardcoded mock screens** with non-functional buttons, and `/orders` fails to join customer profiles because `orders.user_id` references `auth.users(id)` instead of `public.profiles(id)`.

### What Is Broken or Missing
1. **Unapplied Supabase Migrations (`0003` & `0004`):** `public.delivery_locations`, `public.order_status_history`, and RPC `update_delivery_location` **do not exist in the live Supabase database** (`404 PGRST205`).
2. **Customer Order Tracking & Realtime Status:** Completely mocked on Android (`TrackingRepositoryImpl` is an offline `delay(10000)` loop that decrements fake meters; `OrdersViewModel` has a `simulateLiveOrderStatusUpdates` fake timer and never queries `order_items` or `order_status_history`).
3. **Delivery Partner Flow:** `DeliveryPartnerScreen` is **orphaned** (never added to `NavHost` in `MainAppScreen.kt` and no button navigates to it). Even if reached, `DeliveryTrackingService` calls the missing `update_delivery_location` RPC (`404`) and sends a hardcoded fake API key (`X-API-Key: test_api_key_123`).
4. **Guest Persistence & Cart Sync:** Guest mode (`isGuest = true`) is stored only in an in-memory `MutableStateFlow` (`SessionManager.kt`), so **every app restart forces a guest back to the Login screen**. Local Room cart never syncs with Supabase `carts`/`cart_items`.
5. **Security & RLS:** `public.coupons` and `public.delivery_settings` have **RLS disabled** (`anon` can modify or delete all rows). `public.profiles` allows any logged-in user to self-update `role = 'admin'`. Admin `proxy.ts` only checks `if (!user)` and **never checks `role === 'ADMIN'`**, allowing any customer to access the Admin panel. Furthermore, the **Supabase Service Role Key is hardcoded in plaintext** inside 7 untracked root scripts (`seed.js`, `check.mjs`, etc.).

### Overall Completion Estimate
**~32% Complete** (UI shell & local Room cart exist; backend schema, live data integrity, auth/profile lifecycle, checkout integrity, order tracking, delivery partner, security, and half of Admin are incomplete or broken).

### Launch Readiness Verdict
**NO-GO (Critical Blockers Across Database, Auth, Checkout, Tracking, Admin, and Security).**
